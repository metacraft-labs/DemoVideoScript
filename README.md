# DemoVideoScript

Project-neutral scenario format and runner: one script drives UI tests, documentation captures and demo videos on terminal, GUI and browser backends.

> **Status:** the format, its JSON Schemas, the parser and the linter are implemented;
> the runner and the backends are in progress.

A _scenario_ describes what a user does to an application and what they then see:
a declared **stage** that sets up initial conditions, followed by **steps** that are only
user input (keys, chords, typing, pointer gestures), observations of page objects, and
waits on named conditions. The same scenario file runs unchanged against a terminal, a
native window, a web or Electron application, or a WebDriver target, and serves as a UI
test, a test-run recording, a documentation capture, and the raw material of a narrated
video.

This repository holds the format's JSON Schemas, the parser and linter, the single
runner that interprets scenarios, and a small conformance application with its scenario
corpus. Backends live in their own repositories:

- [DemoVideoScript-TermAssert](https://github.com/metacraft-labs/DemoVideoScript-TermAssert) — terminal applications
- [DemoVideoScript-GuiAssert](https://github.com/metacraft-labs/DemoVideoScript-GuiAssert) — native windows
- [DemoVideoScript-Playwright](https://github.com/metacraft-labs/DemoVideoScript-Playwright) — web and Electron applications
- [DemoVideoScript-WebDriverIO](https://github.com/metacraft-labs/DemoVideoScript-WebDriverIO) — WebDriver targets such as VS Code extensions

Videos are produced with [DemoVideoStudio](https://github.com/metacraft-labs/DemoVideoStudio).

## Using it

```sh
dvs lint scenarios/*.yaml --pack my-app.pack.yaml
dvs parse scenarios/archive.yaml        # the normalised form, as JSON
dvs schema scenario > scenario.schema.json
```

The format is described in [docs/users/format-reference.md](docs/users/format-reference.md).
The conformance application's pack and its scenarios, in [`conformance/`](conformance/),
are complete worked examples.

## Developing

Enter the dev shell (`nix develop`, or `direnv allow` with the provided `.envrc`), then:

| Recipe                                         | Does                                                                                                                                                                                                               |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `just build`                                   | builds `build/bin/dvs`                                                                                                                                                                                             |
| `just test`                                    | unit suites, the command-line suite against the built binary, and the check that the published schemas and the parser accept exactly the same files (against independent YAML 1.2 and JSON Schema implementations) |
| `just lint`                                    | schemas up to date with `tools/generate_schemas.py`, `nim check`, the corpus lints clean, the neutrality scan, `nixfmt`                                                                                            |
| `python3 tests/mutation/run-dvs1-mutations.py` | the mutation gate of the format: every planted defect must turn `just test` red                                                                                                                                    |

The schemas are generated by `tools/generate_schemas.py`; edit the generator, not the
JSON.
